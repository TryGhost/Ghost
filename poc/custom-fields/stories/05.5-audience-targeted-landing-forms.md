# Story 5.5 — Audience-targeted landing forms (next iteration)

**Goal:** let owners create **multiple** Landing forms, each targeting an **audience segment** (tier, paid/free, label, signup date, …), so they can ask different things of different members.

**Status:** Not started. The next iteration after [Story 5](./05-landing-form.md) (single Landing form).

**Depends on:** Story 5 (the single-form mechanic: injected card, implicit-pending + dismiss, collection UX, preview).

## Why it's a separate iteration

Story 5 proves the **core mechanic**, which is identical for one form or many: the injected card, pending/dismiss, the collection flow, the preview. Multi-form is **additive on top**: it adds *which field set a member gets*, not *how the card works*. So it's worth shipping the core first, then layering this.

## Shape (the Newsletters pattern)

- The Landing form section becomes a **list** (like Newsletters): each row = one form (name + audience + its fields), with **Edit** and **drag-to-reorder**, and an **"Add landing form"** modal.
- Each form has: a **name**, an **audience filter** (tier / paid / free / label / …, expressed as an NQL-style member filter in a real build), an **enabled** flag, and its own **field list**.

## Precedence (the decided rule)

- **Order in the list = priority.** For a given member, show the **first form whose audience matches**. Drag to reorder.
- **Not** "last created" (non-deterministic feel) and **not** "most specific wins" (breaks when segments overlap without nesting).
- **One form per member at a time** (the first match). A later iteration could surface the next match after completion/dismissal.

## Data model change

`forms.landing` (a single placement list) becomes a **list of forms**, each `{ id, name, audience, enabled, fields: placement[] }`. Cheap to evolve in the localStorage POC; in a real build the audience is an NQL filter and matching runs server-side.

## Out of scope (until built)

Audience-filter builder UI, real NQL matching, analytics per form. Captured here so the precedence + list model is on record.
