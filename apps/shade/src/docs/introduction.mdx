# Shade

<p className="excerpt">Shade is the design system that powers Ghost Admin. Tokens, layout primitives, generic UI controls, and product-shaped patterns — all in one place so designers, engineers, and AI agents stop reinventing them.</p>

## In one screen

- **[Tokens](?path=/docs/tokens-tokens-guide--docs)** — colour, type, spacing, radius, motion. Visual galleries in the sidebar.
- **[Primitives](?path=/docs/primitives-primitives-guide--docs)** — `Stack`, `Inline`, `Box`, `Grid`, `Container`, `Text`. Layout, not chrome.
- **Components** — `Button`, `Input`, `Dialog`, `Tabs`… Generic and accessible. Built on Radix + ShadCN.
- **Patterns** — `PageHeader`, `KpiCard`, `Filters`. Product-shaped compositions.
- **Page templates** — `ListPage`. Top-level page wrappers that compose patterns.

The boundaries between those layers are the whole point. See **[Layers](?path=/docs/overview-layers--docs)** for the decision flow.

## Working in Shade

Shade is the **default source for Ghost Admin UI**. It's already wired into every admin app — just import:

```tsx
import {Button} from '@tryghost/shade/components';
import {Stack} from '@tryghost/shade/primitives';
```

If a control exists, use it. If it doesn't and you'll reuse it, [Layers](?path=/docs/overview-layers--docs) tells you which folder to add it to.

See **[Contributing](?path=/docs/overview-contributing--docs)** for the implementation and review checklist.

## Admin 7 design rollout

Shade uses the Admin 7 design by default. New screens use ordinary `Button`,
`SelectTrigger`, `InputGroup`, `Badge`, `FilterBar`, and `PageHeader` components;
there is no need to add `shape="pill"` or copy Admin 7 classes into pages.
Explicit shapes remain available for a specific visual need. They do not select
an interaction mode.

During the experiment, Admin reads the private flag once at its React application
boundary and passes `isAdmin7Design` to `ShadeApp`. When false, the previous
colors, spacing, tooltip behavior, and control geometry are preserved. Editor and
Ember-owned routes keep this value false, as does the standalone ActivityPub
preview during this experiment.

```tsx
// Only the host reads the private flag. Shade defaults to true when omitted.
<ShadeApp darkMode={darkMode} isAdmin7Design={enabled}>
    <App />
</ShadeApp>
```

Shared components can read `useShade().isAdmin7Design` for temporary structural
or interaction differences. Pure appearance differences belong in shared recipes
and scoped tokens. `Button variant="subtle"` expresses a low-emphasis action:
ghost chrome with Admin 7 enabled, outline chrome otherwise. Avoid using
`controlShape` as a proxy for behavior.

Portals carry their owning React context through Shade's internal scope wrapper
and its `data-admin7-design` attribute. Do not copy design variables onto
`document.body`: two independently mounted surfaces must not change one another's
menus or dialogs. Standalone surfaces should use `ShadeApp` to provide both
context and the CSS scope.

### Removing the experiment

At general availability, remove the Admin flag and route mapping, then remove
`isAdmin7Design` from the host. Shade already defaults to true. Search for
`isAdmin7Design` and keep the enabled branches, then remove the false token scope
and compatibility tests. Remove other host opt-outs once their rollout is
approved. Ordinary screens require no pill-prop migration. Keep Admin 7
interaction tests and canonical PageHeader stories as the permanent contract.
