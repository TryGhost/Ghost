# Shade

<p className="excerpt">Shade is the design system that powers Ghost Admin. Tokens, layout primitives, generic UI controls, and product-shaped patterns — all in one place so designers, engineers, and AI agents stop reinventing them.</p>

## In one screen

- **[Tokens](?path=/docs/tokens-tokens-guide--docs)** — colour, type, spacing, radius, motion. Visual galleries in the sidebar.
- **[Primitives](?path=/docs/primitives-primitives-guide--docs)** — `Stack`, `Inline`, `Box`, `Grid`, `Container`, `Text`. Layout, not chrome.
- **Components** — `Button`, `Input`, `Dialog`, `Tabs`… Generic and accessible. Built on Radix + ShadCN.
- **Patterns** — `PageHeader`, `KpiCard`, `Filters`. Product-shaped compositions.
- **Page templates** — `ListPage`. Top-level page wrappers that compose patterns.

The boundaries between those layers are the whole point. See **[Layers](?path=/docs/overview-layers--docs)** for the decision flow.

## Working in Shade

Shade is the **default source for Ghost Admin UI**. It's already wired into every admin app — just import:

```tsx
import {Button} from '@tryghost/shade/components';
import {Stack} from '@tryghost/shade/primitives';
```

If a control exists, use it. If it doesn't and you'll reuse it, [Layers](?path=/docs/overview-layers--docs) tells you which folder to add it to.

See **[Contributing](?path=/docs/overview-contributing--docs)** for the implementation and review checklist.

## Admin 7 milestones

Shade previews use the new controls by default. New screens use ordinary
`Button`, `SelectTrigger`, `InputGroup`, `Badge`, `FilterBar`, and `PageHeader`
components; there is no need to add `shape="pill"` or copy milestone classes into
pages. Form selects and input groups retain standard rounded corners; their
embedded action buttons inherit the button shape. PageHeader.SelectTrigger supplies
the pill shape for header dropdowns. Explicit shapes remain available for a specific visual need.

Admin enables the current design on all React-owned routes without a Labs flag.
It passes `isAdmin7={false}` on Ember-owned routes, including the editor while
`editorReact` is disabled, to preserve their compatibility appearance. The generic
`isAdmin7` provider switch remains available for these legacy surfaces:

```tsx
<ShadeApp darkMode={darkMode} isAdmin7={isAdmin7}>
    <App />
</ShadeApp>
```

Components can read the same value for structural or interaction differences
required by legacy surfaces:

```tsx
import {useShade} from '@tryghost/shade/app';

const {isAdmin7} = useShade();
```

Pure appearance differences belong in shared recipes and scoped tokens.
`Button variant="subtle"` expresses a low-emphasis action: ghost chrome with
`isAdmin7` enabled, outline chrome otherwise. Avoid using control shape as a
proxy for behavior.

Portals carry `data-admin7` through Shade's internal scope wrapper. Keep
scope attributes off `document.body`: independently mounted surfaces must not
change one another's menus or dialogs. Shade previews and standalone ActivityPub
default to the new appearance. Embedded ActivityPub inherits Admin's computed
boolean from the shared application wrapper.

The [feature flag guide](https://github.com/TryGhost/Ghost/blob/main/docs/practices/feature-flags.md#admin-7-milestones)
covers naming, shared presentation, testing and removal. Retain compatibility
branches while Ember-owned surfaces still need them; ordinary component calls
already use the intended defaults.
