# Shade

<p className="excerpt">Shade is the design system that powers Ghost Admin. Tokens, layout primitives, generic UI controls, and product-shaped patterns — all in one place so designers, engineers, and AI agents stop reinventing them.</p>

## In one screen

- **[Tokens](?path=/docs/tokens-tokens-guide--docs)** — colour, type, spacing, radius, motion. Visual galleries in the sidebar.
- **[Primitives](?path=/docs/primitives-primitives-guide--docs)** — `Stack`, `Inline`, `Box`, `Grid`, `Container`, `Text`. Layout, not chrome.
- **Components** — `Button`, `Input`, `Dialog`, `Tabs`… Generic and accessible. Built on Radix + ShadCN.
- **Patterns** — `PageHeader`, `KpiCard`, `Filters`. Product-shaped compositions.
- **Page templates** — `ListPage`. Top-level page wrappers that compose patterns.

The boundaries between those layers are the whole point. See **[Layers](?path=/docs/overview-layers--docs)** for the decision flow.

## Working in Shade

Shade is the **default source for Ghost Admin UI**. It's already wired into every admin app — just import:

```tsx
import {Button} from '@tryghost/shade/components';
import {Stack} from '@tryghost/shade/primitives';
```

If a control exists, use it. If it doesn't and you'll reuse it, [Layers](?path=/docs/overview-layers--docs) tells you which folder to add it to.

See **[Contributing](?path=/docs/overview-contributing--docs)** for the implementation and review checklist.

## Design rollout and legacy compatibility

Shade's current design is the default. New screens use ordinary `Button`,
`SelectTrigger`, `InputGroup`, `Badge`, `FilterBar`, and `PageHeader` components;
there is no need to add `shape="pill"` or copy current-design classes into pages.
Explicit shapes remain available for a specific visual need. They do not select
an interaction mode.

During the Admin 7 experiment, Admin resolves the private flag once at its
React application boundary and selects `design="current"` or `design="legacy"`
on `ShadeApp`. The legacy boundary preserves the previous defaults, including
colors, spacing, tooltip behavior, and control geometry. Editor and Ember-owned
routes retain the legacy design. Standalone ActivityPub also retains its legacy
boundary during this experiment.

```tsx
// Only the host selects compatibility. Screens do not read the private flag.
<ShadeApp darkMode={darkMode} design={enabled ? 'current' : 'legacy'}>
    <App />
</ShadeApp>
```

Shared components can read `useShade().isLegacyDesign` when temporary structural
or interaction compatibility is necessary. Pure appearance differences belong
in the shared recipes and scoped tokens. `Button variant="subtle"` expresses a
low-emphasis action; it uses ghost chrome in the current design and outline
chrome in the legacy design. Avoid using `controlShape` as a proxy for behavior.

Portals carry their owning React design context through Shade's internal scope
wrapper. Do not copy design variables onto `document.body`: two independently
mounted surfaces must not change one another's menus or dialogs. Standalone
surfaces should use `ShadeApp` to provide both context and the CSS scope.

### Removing the experiment

At general availability, remove the Admin flag and route mapping, then remove
its `design` prop from the host. The current design is already the default.
Delete the legacy branches, legacy token scope, and compatibility tests in Shade,
and remove any other host compatibility opt-outs once their rollout is approved.
Ordinary screen components require no pill-prop migration. Keep current-design
interaction tests and canonical PageHeader stories as the permanent contract.
